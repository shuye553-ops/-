# 部署、移动备份与回滚

本次资料迁移不部署或重新构建游戏文件。当前游戏路径由本地配置指定；现有安装保持与迁移前一致。

## 五文件依赖

必须成套处理 `masterbank.bank`、`masterbank.assets.bank`、`masterbank.strings.bank`、`tanks_engines.bank`、`tanks_engines.assets.bank`。其中两个master配套文件可能未变，仍作为依赖一起交付。不要只换metadata或assets，不混用不同批次。

辅助Studio项目会生成含辅助事件名称的strings；不能将它替换进成品，成品沿用基线master strings。飞机和其他效果bank未修改。

## 已授权部署的事务

1. 检查游戏aces进程已关闭，不擅自结束用户游戏。
2. 核对静态/运行库报告、72父调度验收与当前输出SHA，确认安装仍匹配上次收据。
3. 在游戏mod目录下建立本次独立暂存目录，复制待部署五件并验证hash。
4. 用独占读打开原文件确认无占用；将五个现有对应文件**移动**到制作工程带时间戳的deployment-backups。
5. 每个移动原件验证旧hash，记录阶段与已移动名单，再将暂存件移至安装位置。
6. 核对所有新hash和其他未改bank；从安装位置做原生加载/预载；保存收据。
7. 任一步失败，将本次已经移动的原件复制恢复到原位，验证；备份不删除，保留失败记录。

这不等于移动整个游戏sound目录或改游戏配置。`config.blk` 已启用自定义声音，不在当前资料迁移中修改。

## 当前可回滚层次

- `deployment-backups/20261022-201830`：第一次更新之前的原始安装五件。
- `deployment-backups/20261022-210550`：用户已经实测正常的前一版五件，含当时新增声音；当前本地录音版之前的直接回滚点。
- `baseline/package` 与 `inputs/original-package`：初始十个bank受保护副本/原包。

迁移后备份都在 `maintenance/` 内。不要继续执行旧E路径的命令；备份restore脚本会用自身目录读deployment.json，迁移修正了操作性收据路径。旧日志保留原来路径作为历史。

## 手动回滚

退出游戏，执行选中备份目录的restore.ps1。脚本先核对备份hash，确认当前安装是对应的新/旧版本，才恢复五文件；若之后又装了其他版本则停止，不覆盖未知新状态。恢复后hash必须等于该备份的oldHashes。

制作根目录移动只改变素材/工具/备份的路径，安装路径仍由配置控制。没有新部署任务时，不需要为了迁移而重装已正常工作的声音包。
